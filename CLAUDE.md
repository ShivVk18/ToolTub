## Where things are

- Reference UI: `design/reference/KlipKit_UI.html` (the source of truth for pixels and behaviour).
- Agent prompts and specs (local only, not in git): `docs/agent/` — start with `00_START_HERE.md`; engineering standards in `03_ENGINEERING_STANDARDS.md`.
- Visual baseline after the Hallmark pass: `design/reference/v2/` (allowed differences: ADR 0005).
- Decisions: `docs/adr/`. PR bodies and changelog: `reports/prs/`, `reports/changelog.md`.
- Test reports: `reports/tools-e2e-report.md` (narrative), plus JSON and HTML generated by `scripts/tools-report.ts` (ADR 0007).
- Adding a tool: README, "Add a tool in 5 steps".

## Rules

- One branch + one PR per fix, branched from and squash-merged into `integration/ui-restore`. Never commit to `main`, never force-push, never `git reset --hard`, never delete files without asking.
- Reproduce → root cause → failing test → fix → re-test. Never weaken or delete a test.
- Verify output, not just page load: a tool passes only if its result was checked.
- No third-party APIs, CDNs or AI servers. Fonts via `next/font/local`. Plans: Free and Pro only.
- Ask before adding a dependency over 100 KB or changing server/infra.
- Tool logic lives in pure engines (`src/lib/engines`); one tool registry (`src/registry`); one rAF loop.
- Before shipping a UI change, run the visual compare (and the design audit) against the reference.
- Plans never fake results: a step runs, opens another tool, or says "Coming soon" (ADR 0006).

## Gotchas

- After CSS changes, `rm -rf .next/cache/turbopack` before `npm run build`; Turbopack's persistent cache serves stale CSS.
- Unlayered CSS in `globals.css` beats Tailwind utilities. Put resets in a layer; only deliberate overrides stay unlayered.
- Start the production build with `npm start` (`scripts/start-standalone.mjs`), not `.next/standalone/server.js` directly: that one has no static files.
- Run TS scripts with `npx jiti <file>` (Node's type stripping can't resolve extensionless imports), and don't import with a `.ts` extension: `next build` type-checks `scripts/` too.
- Sizes on the home page use KB = 1000 bytes (`fmtSize`); tool pages and workers use KiB.
- Tests that open the reference page are slow under parallel load (its teardown alone can take a minute); they have a 240 s budget.
- Firefox doesn't launch on macOS 27 locally; it runs in CI.

## Commands

- `npm run verify` — typecheck, lint, unit tests, build (must be green before every PR)
- `npm run test:e2e` — Playwright on the production build (`npm run test:all` = verify + e2e)
- `npm run visual` — visual compare against the reference (app must be running; see the script)
- `npm run format` — Prettier
- `npm run test:perf` — Lighthouse CI (budgets in `lighthouserc.cjs`)
- `npx jiti scripts/tools-report.ts` — rebuild the tools report JSON and HTML from the last Playwright run
