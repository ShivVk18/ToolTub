## 6. Privacy results

A network guard (`tests/e2e/helpers.ts`) records every request. `assertClean()` fails the test on any request to another origin, any failed request or any console error. `assertNoUpload()` fails it on any request that carries a body. The guard runs in the universal checks for every tool page (`tools.spec.ts`), and in `plan.spec.ts`, `platform.spec.ts` and `perf-privacy.spec.ts`. It does not run in every spec: the redesign and visual suites don't use it.

- **Third-party domains seen: none**, in every guarded test, on all 4 browser projects.
- **Live panels (18):** one page, every panel run 5 times: **0 requests with a body**, 0 third-party, 0 failed requests, 0 console errors (`perf-privacy.spec.ts`).
- **On-device tools** (image ×4, Compress PDF, QR, JSON, JWT, Background Remover): **0 uploads**. The only requests are the page's own assets, plus the self-hosted model for Background Remover.
- **PDF to Word** is the only tool that uploads, to KlipKit's own server (`/api/jobs`). Files are deleted within the retention window (sweeper tested in `worker-sweep.test.ts` and `server-tools.spec.ts`).
- **Fonts** are self-hosted (`next/font/local`); no CDN requests.

**Budgets:** performance ≥ 90, accessibility and best practices ≥ 95, CLS ≤ 0.05 and SEO 100 on indexable pages are met everywhere. **LCP ≤ 2 s is not met: it is the only failing assertion (14 of 14 pages), so the CI Lighthouse step fails.**

**What the LCP number means.** The 3.4 s is Lighthouse's *simulated* estimate. Unthrottled, LCP happens at first paint (118 ms), and the LCP element is plain text (the tool page's intro paragraph); 87% of the estimate is "render delay". Measured with real throttling instead (`--throttling-method=devtools`: slow 4G, 4× CPU), LCP is **2.1 s on the home page and 1.8 s on Image Compressor**, equal to first paint. So the real number is at or just over the budget, not 70% over. To get under it in both modes, less has to load before first paint (two serif fonts plus Geist, about 140 KB, and the CSS). That's a design-level change (font loading), so it's listed under §5 for your decision rather than done here.

**Slowest tools** (live panels, median ms): Hash Generator 5, Cron Builder 2, JSON Formatter 1, JWT Decoder 1, Timestamp 1; the other 13 are 0.1. Tool pages do their work in workers. Their budgets are checked by `tools.spec.ts` (for example the 5 MB JSON above, and image and PDF jobs that finish with a verified output).

## 8. How to re-run

1. Install once: `npm ci` and `npx playwright install --with-deps chromium webkit firefox`.
2. Unit tests, typecheck, lint and build: `npm run verify`.
3. All end-to-end tests on the production build: `npm run test:e2e`. To match this report exactly: `npm run build && npx playwright test --project=platform --project=chromium --project=webkit --project=mobile-pixel7 --project=mobile-iphone14 --workers=4`.
4. Rebuild this report's data and HTML from that run: `npx jiti scripts/tools-report.ts` (reads `test-results/results.json` and `test-results/perf.json`, writes `reports/tools-e2e-results.json` and `reports/tools-e2e-report.html`).
5. Lighthouse: `npm run test:perf`.
6. Accessibility only: `npm run test:a11y`. Open the last Playwright report: `npm run test:report`.

**CI:** `.github/workflows/test.yml` runs all of this on every push and pull request (Ubuntu, with Firefox, Valkey and LibreOffice) and uploads `playwright-report/`, `reports/` and the Lighthouse reports as artifacts.
